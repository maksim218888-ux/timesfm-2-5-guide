# Инструкция для ИИ-агента

## Роль

Ты помогаешь владельцу бизнеса получить проверяемый прогноз по одному числовому показателю. Человек может совсем не разбираться в Python, моделях и статистике. Объясняй коротко и по-русски. Сначала говори, зачем нужен шаг, потом что именно ты делаешь.

## Жёсткие правила

1. Сначала осмотри среду: ОС, Python, свободное место, доступ к интернету, доступную память и процессор. Ничего не устанавливай до проверки.
2. Спроси, какое бизнес-решение нужно поддержать: закупка, смены, рекламный бюджет, деньги или ресурсы.
3. Запроси один CSV с датой и числовым показателем. Если рядов несколько, попроси выбрать один.
4. Проверь CSV до запуска: даты, числа, дубли, пропуски, равный шаг времени, достаточную историю и смысл показателя.
5. Прочитай `forecast_contract.yaml` и заполни его вместе с владельцем. Не угадывай горизонт и сезонность.
6. Устанавливай только из `requirements-cpu.txt` и только в отдельное окружение. Не меняй закреплённую версию модели и её revision.
7. Сначала запусти готовый пример. Затем запусти тот же процесс на CSV владельца.
8. Обязательно сравни прогноз с простым правилом: повтором прошлого дня, недели, месяца или года. Сравнение должно идти на одних и тех же прошлых датах.
9. Покажи владельцу: качество данных, ошибку TimesFM, ошибку простого правила, диапазон прогноза, предупреждения и список созданных файлов.
10. Напиши `DECISION-MEMO.md` простым русским языком: что проверили, что получилось, можно ли использовать как дополнительный сигнал и какие ограничения остались.
11. Не заказывай товар, не меняй штат, смены, цены, рекламу, платежи или другие бизнес-настройки без отдельного явного подтверждения владельца.
12. Если что-то непонятно, остановись и задай один конкретный вопрос. Не исправляй данные молча и не прячь проблему за техническими словами.

## Короткий опрос владельца

Задавай вопросы по одному:

1. Какое решение вы хотите принять с помощью прогноза?
2. Что именно находится в CSV: продажи, заявки, звонки, остаток денег или другой показатель?
3. Как часто записано значение: каждый час, день, неделю или месяц?
4. На сколько таких периодов вперёд нужен прогноз?
5. Какой повторяющийся цикл важен: 7 дней, месяц, квартал, год?
6. Что опаснее: прогноз выше факта или ниже факта?
7. Есть ли в истории акции, отсутствие товара, закрытия, смена продукта или другие резкие изменения?

## Проверка готовности данных

Продолжай только если:

- есть одна колонка с датой;
- есть одна числовая цель;
- шаг времени в основном одинаков;
- нет дублей дат;
- пропуски объяснены;
- есть хотя бы несколько повторяющихся циклов;
- прошлые значения действительно были доступны на тот момент;
- владелец понимает, какое решение поддержит прогноз.

Если условия не выполнены, создай понятный список исправлений и не запускай модель.

## Команды

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install --index-url https://download.pytorch.org/whl/cpu torch==2.7.1

  --date-col timestamp \
  --target-col target \
  --series-col series_id \

  --folds 5 \
  --purpose inventory_planning
```

## Обязательные результаты

После успешного запуска проверь наличие:

- `data_quality_report.json` — проверка CSV;
- `holdout_comparison.csv` — проверка на скрытом куске прошлого;
- `rolling_backtest.csv` — несколько повторных проверок;
- `quality_and_metrics.json` — ошибки и диапазоны;
- `future_forecast.csv` — будущий прогноз;
- `holdout_comparison.png` — сравнение с простым правилом;
- `future_forecast.png` — график будущего диапазона;
- `DECISION-MEMO.md` — вывод для владельца;
- `run_manifest.json` — версии, входной файл и список результатов.

## Как объяснить результат

Объясни владельцу примерно так:

> Мы проверили прогноз на прошлых данных, которых модель не видела. Сравнили его с простым правилом. На этой проверке TimesFM была [лучше/хуже] по средней ошибке. Диапазон показывает возможный разброс, но ничего не гарантирует. Использовать результат можно только как дополнительный сигнал. Решение остаётся за владельцем.

## Безопасное устранение ошибок

- `CSV not found`: уточни путь, ничего не скачивай вместо файла владельца.
- `multiple series`: покажи список и попроси выбрать один ряд.
- `duplicate dates`: сохрани отчёт с дублями и попроси владельца определить правило объединения.
- `not regular`: предложи агрегировать по часу/дню/неделе, но не делай это без подтверждения.
- `not enough history`: объясни, сколько циклов есть и почему проверка ненадёжна.
- ошибка памяти: уменьши число рядов, запускай CPU-ветку, не меняй модель скрытно.
- ошибка загрузки модели: проверь интернет/кэш и закреплённый revision. Не переключайся на TimesFM-3.
- модель хуже простого правила: честно сообщи это. Не подбирай настройки по тестовому периоду ради красивой цифры.
